# Synorch v0.3.0

Synorch v0.3.0 turns generated orchestration structures into explicit, machine-checkable contracts. Agents and skills now carry canonical frontmatter and required sections, `doctor` validates those contracts and their size boundaries, and the new Skill Creator workflow can promote repeatedly confirmed project knowledge into evidence-backed local skills.

## Highlights

- Defines Canonical Agent Manifest v1 and Canonical Skill Contract v1.
- Validates generated agents, base skills, project skills, declared references, and per-layer byte ceilings through `doctor`.
- Adds `skill-creator` as the ninth canonical base skill.
- Seeds a Git-tracked observation ledger at `.ai/tasks/observations.yaml` without overwriting existing observations.
- Promotes project knowledge only after three confirmations from distinct tasks, or immediately when the user supplies a correction.
- Requires generated skills to cite in-root evidence with matching digest prefixes and valid confirming task ids.
- Keeps generated project skills under user control: `sync` does not create, overwrite, or delete them, even with `--force`.
- Prunes expired, unpromoted observations during `sync` while preserving promoted and declined records.
- Improves diagnostics with dedicated codes, safe reference resolution, promotion-link validation, and concise schema errors.

## Contract changes

Agent manifests and base skills now expose their contracts in frontmatter instead of relying on prose alone. Existing hand-written agents under `.ai/agents/` must provide a valid `AGENT.md`, use a name matching their directory, reference known skills, and include the required sections.

Generated project skills live under `.ai/skills/project/` and carry their own activation state. There is no project-skill registry entry; activation is expressed with `status: active` in skill frontmatter and `status: promoted` plus an optional `promoted_to` link in the observation ledger.

## Upgrade an existing Synorch structure

This release changes generated contracts. Commit or back up the target repository first, then regenerate and validate the structure:

```bash
npx synorch@0.3.0 inspect --target .
npx synorch@0.3.0 init --target . --force
npx synorch@0.3.0 sync --target . --force
npx synorch@0.3.0 doctor --target .
```

Review the resulting diff before committing it. The `--force` flags replace modified canonical generated files, but the observation ledger and generated project skills remain preserved.

## Start a new structure

```bash
npx synorch@0.3.0 init
npx synorch@0.3.0 sync
npx synorch@0.3.0 doctor
```

Or update the global CLI:

```bash
npm install --global synorch@0.3.0
syn --version
```

Node.js 24 or newer is required.
