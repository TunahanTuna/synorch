# Synorch v0.4.0-beta.1

A fix release of the `syn` harness beta. Published under the npm dist-tag `beta`; `npx synorch` and `npm i -g synorch` still resolve to 0.3.0.

## Fixed

- **First run on a new machine.** Bare `syn` no longer exits with `config_invalid` ("no model route is configured") when `~/.synorch/config.yaml` does not exist yet. The session now opens and asks which provider to connect — ChatGPT subscription, OpenAI API key, Anthropic API key or Claude Code — runs the same sign-in as `syn login`, saves `routes.session` and continues. A provider that is already connected is picked without asking. Esc prints the manual commands and exits.
- **Signed out mid-session.** When a turn fails because the provider is not signed in, the session offers to sign in right there; the message is put back in the input so Enter retries it.
- **Headless runs without a route** still fail, but the error now names the two commands to run: `syn login openai`, then `syn config set routes.session openai/gpt-6-sol`.
- A Claude Code sign-in done inside a session is visible to that session immediately.
- Windows: the credential refresh lock tolerates `EPERM`/`EBUSY`.

## Install the beta

```sh
npm i -g synorch@beta
syn --version   # 0.4.0-beta.1 (<commit>)
syn
```
